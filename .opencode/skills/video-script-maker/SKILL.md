# 影片腳本前製（大綱 → 審校 → 封標）

你同時是選題顧問、編劇教練和封標策略師。這支技能覆蓋影片動工前的全部案頭工作：**大綱方案、口語化審校、標題封面與內容承接檢查**。做完這三步，腳本才交給製片技能（`short-video-maker` / `knowledge-video-factory`）去出片。

## 流程總覽

```
Step 1  大綱生成    → 2-3 個方案（標題/封面建議/結構/時長）
Step 2  腳本初稿    → 使用者自備，或由 short-video-teardown（爆款拆解）產出
Step 3  口語化審校  → 三遍審校：內容 → 口語化 → 演示標注
Step 4  封標檢查    → 標題（5 公式）+ 封面（結果展示）+ 承接（懸念後置）
```

不需要每支影片都跑全套：只要大綱就停在 Step 1；腳本已口語就跳過 Step 3。**等待使用者選擇方案，不替使用者假設。**

---

## Step 1：大綱生成

快速生成 2-3 個腳本大綱方案，每個方案不同角度。

### 方案模板

```markdown
## 方案 N：[吸引人的標題]
**封面建議**：結果展示 / 人臉（根據粉絲量）
**核心角度**：xxx
**時長預估**：⏱️ 5-8 分鐘

### 大綱結構
1. 開頭（30 秒-1 分鐘）：確認標題承諾 + 建立懸念
2. 核心模組 1（2 分鐘）：xxx
3. 核心模組 2（2 分鐘）：xxx
4. 意外驚喜（1 分鐘）：超出預期的內容
5. 結尾（1-2 分鐘）：兌現承諾 + Call to Action

### 需要演示的內容
- 演示 1：xxx

### 優勢劣勢
✅ 優勢：xxx
⚠️ 劣勢：xxx
```

- 應用「內容承接策略」（開頭確認 → 中段驚喜 → 結尾兌現，見 Step 4）
- 時長預估要合理（口播約 150-180 字/分鐘）
- **列出方案後等待使用者挑選，不擅自定稿**

---

## Step 2：腳本初稿

三種來源，依情況選：

1. **使用者自備腳本** → 直接進 Step 3
2. **需要從爆款學** → 用 `short-video-teardown` 拆解競品影片，生成腳本+分鏡後回到這裡審校
3. **只要通用寫法** → 參考 `short-video-teardown` 內的已驗證公式庫（`references/proven-formulas.md`）選品類基線

---

## Step 3：口語化審校（三遍）

核心目標：**去掉書面語，適合大聲說出來不卡頓，像人在鏡頭前說話。**

### 第一遍：內容審校
- [ ] 事實準確、演示可行
- [ ] 邏輯清晰、步驟連貫
- [ ] 時長合理（150-180 字/分鐘）

### 第二遍：口語化審校（核心）

**刪除書面語**：

| ❌ 書面語 | ✅ 口語 |
|---------|--------|
| 接下來我們將進行... | 我們來... |
| 進行操作 | 點擊 |
| 實現功能 | 做到 |
| 綜上所述 | 直接總結 |

**加入口語詞**：「其實」、「你看」、「這裡」、「那麼」、「說實話」、「我之前」、「這個很關鍵」

**適合說出來**：
- 短句為主（不超過 20 字）
- 用句號斷句，不用逗號連長句
- 大聲讀一遍，卡頓的地方重寫

**改寫示例**：

```
❌ 接下來我們將進行 Claude Code 的安裝操作。首先，打開終端，然後輸入相應的命令...

✅ 好，我們來裝 Claude Code。很簡單，打開終端，輸入這個命令...（切螢幕）你看，就這樣。
```

### 第三遍：演示標注
- [ ] 標注哪裡切螢幕、哪裡特寫
- [ ] 檢查節奏和停頓
- [ ] 模擬實際錄製流程

## Step 4：封標與承接檢查（MrBeast 策略）

三大維度：標題（強對比）→ 封面（結果展示優先）→ 內容承接（懸念後置）。

### 4-1 標題檢查：5 種強對比公式

**核心原則：聚焦最強對比，不羅列所有內容。**

| # | 公式 | 格式 | 示例 | 適用 |
|---|------|------|------|------|
| 1 | 數量對比 | 小數量 vs 大數量 | 「1 個 Prompt 寫了 1000 行代碼」 | 教程/效率/工具 |
| 2 | 價格對比 | 低價 vs 高價 | 「200元 vs 2萬元的AI，差距有多大？」 | 評測/對比 |
| 3 | 結果對比 | 低成果 vs 高成果 | 「30萬粉 vs 0粉，我只做對了這一件事」 | 經驗/成長 |
| 4 | 強弱對比 | 新手 vs 專家 | 「新手 vs Cursor：誰能更快寫完？」 | 挑戰/實驗 |
| 5 | 時間對比 | 短 vs 長 | 「3分鐘 vs 3小時：AI 編程真的更快嗎？」 | 教程/效率 |

**標題類型選擇表**：

| 內容類型 | 推薦標題 |
|---------|---------|
| 教程類 | 結果對比、時間對比 |
| 評測類 | 價格/性能對比 |
| 挑戰類 | 強弱/數量對比 |
| 經驗分享 | 結果對比 |

**避免的標題**：
- ❌ 羅列式：「Cursor 的 5 個常用功能」→ 聚焦 1 個最強功能
- ❌ 平淡式：「Cursor 使用教程」→ 加入結果對比
- ❌ 抽象式：「AI 編程的未來趨勢」→ 具體化場景

**標題檢查清單**：
- [ ] 有明確的對比/衝突？
- [ ] 聚焦 1 個核心點（不羅列）？
- [ ] 能讓人想像出畫面？
- [ ] 建立了懸念？
- [ ] 長度 15-25 字（不超過 30 字）？
- [ ] 真實（能在影片中兌現）？

### 4-2 封面檢查：結果展示優先

**人臉封面適用條件**（謹慎使用）：
- ✅ 粉絲量 > 10 萬（人臉有品牌價值）、挑戰/Vlog/強情緒內容、表情極端且一致
- ❌ 粉絲量 < 10 萬、技術教程類（結果比情緒重要）

**結果展示封面**（優先測試）：
- 教程類：Before/After 對比
- 評測類：產品特寫 + 核心數據
- 技術類：代碼/介面截圖 + 結果展示

**設計要素**：
1. **強對比**：冷暖色（藍+橙）、大小、數字（30萬 vs 0）
2. **視覺聚焦**：1-2 個核心元素，明確視覺重心
3. **文字簡潔**：0-5 個字，固定字體
4. **風格一致**：固定色系、固定佈局、固定字體

**封面檢查清單**：
- [ ] 類型符合內容和粉絲量？
- [ ] 有強對比？
- [ ] 視覺聚焦明確？
- [ ] 文字簡潔？
- [ ] 風格與歷史封面一致？
- [ ] 與標題呼應？

**A/B 測試**：同支影片準備 2 個封面（人臉 vs 結果展示），記錄點擊率。

### 4-3 內容承接檢查：懸念後置

**核心原則：開頭建立懸念，中段超出預期，結尾兌現承諾。**

```
標題/封面：核心懸念（最強對比）
  ↓
開頭（前 30 秒-1 分鐘）：確認標題內容存在 → 建立懸念 → 預告後續
  ↓
中段：主要內容 + 意外驚喜 + 持續提醒懸念（「快了，馬上就到...」）
  ↓
結尾（最後 1-3 分鐘）：兌現標題承諾 → 總結 → CTA
```

**時長控制表**：

| 影片總時長 | 開頭確認 | 中段內容 | 結尾兌現 |
|-----------|---------|---------|---------|
| 3-5 分鐘 | 30 秒 | 2-3 分鐘 | 1 分鐘 |
| 5-10 分鐘 | 1 分鐘 | 6-7 分鐘 | 2 分鐘 |
| 10-15 分鐘 | 1-2 分鐘 | 8-10 分鐘 | 3 分鐘 |

**常見錯誤（必須避免）**：

| 錯誤 | 後果 | 正確做法 |
|------|------|---------|
| 開頭完全不提標題內容 | 觀眾不知何時出現 → 中途退出 | 前 30 秒-1 分鐘確認承諾 |
| 開頭就全部講完 | 後面沒懸念 → 觀看時長短 | 懸念後置到結尾 |
| 標題說 A，影片全是 B | 欺騙感 → 掉粉 | 標題必須兌現 |
| 懸念拖太久 | 觀眾失去耐心 | 根據時長合理分配 |

**承接檢查清單**：
- [ ] 開頭 30 秒-1 分鐘內提到標題核心內容？
- [ ] 建立了明確懸念？
- [ ] 中段有意外驚喜？
- [ ] 結尾兌現承諾？
- [ ] 懸念後置時長合理？
- [ ] 有持續提醒懸念？
- [ ] 結尾有 CTA？

### 4-4 綜合評估

- [ ] 標題、封面、內容三者一致？
- [ ] 能吸引使用者點擊？
- [ ] 能讓使用者看到結尾？
- [ ] 有明確的價值主張？

## 腳本完成後：接製片管線

```
video-script-maker（本技能）
  → short-video-maker（三情境短片快製：活動紀錄/教學/社群科普）
  → knowledge-video-factory（知識影片工廠：4K 自動化長片）
  → 需要藝術風格動畫片段時 → code-animation-director（程式碼動畫導演）
```
